# Масштабирование: Очередь парсинга

## Текущее поведение
При `activeParsings >= MAX_CONCURRENT` → ответ 429 «Сервер занят».

## Целевое поведение
Вместо отказа — ставить запрос в очередь. UI показывает позицию в очереди и примерное время ожидания.

## План реализации

### 1. Очередь на Redis (Bull/BullMQ)
```bash
npm install bullmq
```
- Создать очередь `parsing-queue` в Redis
- При запросе на парсинг — добавить Job в очередь
- Worker обрабатывает по `MAX_CONCURRENT` задач одновременно

### 2. Новый endpoint — позиция в очереди
```
GET /api/queue/:sessionId → { position: 3, estimatedWait: "~5 мин" }
```

### 3. Обновление UI
- Показывать «Вы 3-й в очереди» вместо ошибки
- Автоматически начинать парсинг когда подошла очередь
- Прогресс-бар ожидания

### 4. Среднее время парсинга
Трекать среднее время парсинга для расчёта `estimatedWait`:
```
estimatedWait = position * avgParsingTime / MAX_CONCURRENT
```
